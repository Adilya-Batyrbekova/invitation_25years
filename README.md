## GitHub Pages publication

Target URL: `https://adilya-batyrbekova.github.io/invitation_25years/`. Until a successful Pages deployment is verified, this is the configured target rather than a claimed live site. `.github/workflows/invitation-pages.yml` runs checks, builds with the repository prefix, verifies the production build and uploads only `invitation/dist` for Pages. Main pushes affecting the application or workflow and manual workflow dispatch trigger deployment. Source visibility is separately owner-authorized as public.

Build locally with `node scripts/task.mjs build:pages`; verify it with `node scripts/task.mjs pages`, from `invitation/`. The production smoke tests serve the build at the actual repository prefix and use isolated browser contexts without submitting data. Set `PAGES_TEST_URL` to the deployed URL to run those same non-writing checks remotely. GitHub Settings → Pages must use GitHub Actions. No custom domain, account purchase or separate repository is required.

For a bad deployment, unpublish Pages in GitHub Settings while retaining source/history, or review and deploy a corrective commit. A source revert alone does not remove public Git history. Forms still report unavailable persistence and do not claim saved answers or reservations.
